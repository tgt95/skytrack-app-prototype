# Mission Studio architecture

Short source map for agents working on the Mission Studio prototype. Code is source of truth; update this note when structure or behavior changes.

This repository is the standalone Mission Studio app. Its entry, shell, route, domain, modules, and shared code live directly under `src/`. It does not use Prototype Hub routing or shared state.

## Architecture

- [`index.tsx`](../../src/index.tsx) composes route and stage behavior: [`use-studio-routing.ts`](../../src/modules/studio/use-studio-routing.ts) owns browser-history routing and Library entry data, [`use-studio-document.ts`](../../src/modules/studio/use-studio-document.ts) owns mission state and history, [`use-drawing-session.ts`](../../src/modules/studio/use-drawing-session.ts) owns transient drawing state, and [`use-mission-commands.ts`](../../src/modules/studio/use-mission-commands.ts) composes mission-edit commands. [`studio-shell.tsx`](../../src/modules/studio/studio-shell.tsx) composes the Studio page from the top bar, left rail, map overlays, scene viewport, inspector, dialogs, and status footer; [`studio-library-route.tsx`](../../src/modules/studio/studio-library-route.tsx) adapts Library routes. State owners and render boundaries live under [`modules/studio/`](../../src/modules/studio). Address search state and controls live in [`modules/search/use-address-search.ts`](../../src/modules/search/use-address-search.ts) and [`modules/search/address-search-controls.tsx`](../../src/modules/search/address-search-controls.tsx). Global mission keyboard handling lives in [`modules/studio/use-mission-keyboard.ts`](../../src/modules/studio/use-mission-keyboard.ts); its listener reads the latest committed state without re-registering on each render. [`use-mission-studio-test-bridge.ts`](../../src/modules/studio/use-mission-studio-test-bridge.ts) maintains the public `window.__missionStudio` hooks. [`modules/library/router.ts`](../../src/modules/library/router.ts) maps Home, Recent, workspace resources, template, shared-project, shared-account, and mission URLs. `/mission/:missionId` is the canonical mission URL; `/detail/:missionId` and `/mission-studio/:missionId` are legacy aliases.
- `main.tsx` loads global styles, applies [`shared/theme-preference.ts`](../../src/shared/theme-preference.ts) before rendering, and mounts [`App.tsx`](../../src/App.tsx). App owns the prototype password gate and login shell; [`modules/auth/login-drone.tsx`](../../src/modules/auth/login-drone.tsx) owns the Three.js login illustration and its renderer lifecycle. Library account settings use the same theme-preference helper.
- [`modules/dev-tools/`](../../src/modules/dev-tools) owns the development-only scenario registry, per-scenario metadata folders and optional action components, floating trigger, and searchable Drawer. Add each scenario under `scenarios/<id>/` and register its definition in `scenario-registry.ts`; declare its intended UI placement with a slot from `scenario-slots.ts`, then mount `DevScenarioSlot` at that feature surface. The slot host renders only enabled actions registered for that location, so scenario behavior stays modular and appears in the screen UI it changes rather than beside the floating Dev Tool. Shared keyed state lives in [`shared/dev-scenario-state.tsx`](../../src/shared/dev-scenario-state.tsx).
- `index.html` provides the initial page title and links the SkyTrack mark at `public/favicon.svg`; the route shell replaces the title with the active page or record name.
- [`domain/mission-model.ts`](../../src/domain/mission-model.ts) remains the compatibility barrel for the public mission-domain API. Types/defaults and route sequence helpers live in [`mission-types.ts`](../../src/domain/mission-types.ts); coordinate and route metrics live in [`geo-math.ts`](../../src/domain/geo-math.ts); photogrammetry geometry lives in [`area-scan.ts`](../../src/domain/area-scan.ts); Avoid routing lives in [`avoid-detour.ts`](../../src/domain/avoid-detour.ts); gates, validation, and snapshot hydration live in [`mission-validation.ts`](../../src/domain/mission-validation.ts); Code JSON conversion lives in [`mission-serialization.ts`](../../src/domain/mission-serialization.ts). Keep these modules pure and import through the barrel unless another domain module needs a helper directly.
- [`domain/mission-data.ts`](../../src/domain/mission-data.ts) provides the local seed mission and fixture geometry.
- [`modules/scene/mission-scene.tsx`](../../src/modules/scene/mission-scene.tsx) owns Viewer creation/destruction callbacks, React refs/effects, basemap loading, and the scene host. It calls [`scene-viewer-runtime.ts`](../../src/modules/scene/scene-viewer-runtime.ts) for Cesium setup, listeners, render-loop, and cleanup orchestration; that runtime receives the Viewer factory and destructor from `MissionScene` and creates the shared click-vs-drag record. Camera arbitration lives in [`scene-camera-gestures.ts`](../../src/modules/scene/scene-camera-gestures.ts). [`scene-edit-gestures.ts`](../../src/modules/scene/scene-edit-gestures.ts) remains the public entity-pick/edit integration boundary: it composes handlers, installs the Cesium/canvas/window listeners, consumes the runtime-owned shared record, and disposes those listeners idempotently. The public imperative camera/drag API remains in [`mission-scene-handle.ts`](../../src/modules/scene/mission-scene-handle.ts); scene contracts are in [`mission-scene-types.ts`](../../src/modules/scene/mission-scene-types.ts).
- Gesture behavior is split by lifecycle. [`scene-surface-pick.ts`](../../src/modules/scene/scene-surface-pick.ts) owns scene surface picking and ENU/pick-ray math; [`scene-hover-guide.ts`](../../src/modules/scene/scene-hover-guide.ts) updates photo emphasis and waypoint ground-guide entities; [`scene-point-drag.ts`](../../src/modules/scene/scene-point-drag.ts) owns authored-waypoint, pending-point, and Z-drag state/preview/commit; [`scene-avoid-height-drag.ts`](../../src/modules/scene/scene-avoid-height-drag.ts) owns avoid-height drag preview/commit; [`scene-hover-flow.ts`](../../src/modules/scene/scene-hover-flow.ts) and [`scene-click-flow.ts`](../../src/modules/scene/scene-click-flow.ts) preserve the ordered pointer-hover and click flows. These helpers read live refs and receive the shared drag record; they do not install listeners or create/destroy the Viewer.
- Entity drawing is split by owner: [`sync-world-terrain.ts`](../../src/modules/scene/sync-world-terrain.ts), [`sync-committed-layer.ts`](../../src/modules/scene/sync-committed-layer.ts), [`sync-capture-layer.ts`](../../src/modules/scene/sync-capture-layer.ts), and [`scene-draft-sync.ts`](../../src/modules/scene/scene-draft-sync.ts). [`scene-entity-ownership.ts`](../../src/modules/scene/scene-entity-ownership.ts) classifies and removes only the requested entity layer. [`mission-scene-helpers.ts`](../../src/modules/scene/mission-scene-helpers.ts) contains coordinate conversion, entity-ID parsing, marker images, and search-pin helpers without owning the Viewer. [`basemaps.ts`](../../src/modules/scene/basemaps.ts) holds shared map-style metadata independently from [`mission-map-2d.tsx`](../../src/modules/scene/mission-map-2d.tsx), the dormant Leaflet editing component and its CSS; the main Studio scene remains Cesium and no longer imports the Leaflet module just to read basemap metadata.
- [`modules/design/`](../../src/modules/design) contains inspector composition and feature views. [`design-panel.tsx`](../../src/modules/design/design-panel.tsx) selects mission settings, route/area/avoid cards, Recon settings, and Code views while preserving the parent commit/preview callbacks; [`use-design-panel-state.ts`](../../src/modules/design/use-design-panel-state.ts) owns transient Recon editing state. [`route-sequence-card.tsx`](../../src/modules/design/route-sequence-card.tsx) renders each Route block and delegates draggable waypoint/action rows to [`sequence-controls.tsx`](../../src/modules/design/sequence-controls.tsx). Area and Avoid forms live in [`area-inspector-card.tsx`](../../src/modules/design/area-inspector-card.tsx) and [`avoid-inspector-card.tsx`](../../src/modules/design/avoid-inspector-card.tsx); mission checks/settings and script/JSON views live in [`mission-settings-card.tsx`](../../src/modules/design/mission-settings-card.tsx) and [`code-inspector-panel.tsx`](../../src/modules/design/code-inspector-panel.tsx). [`route-draft-panel.tsx`](../../src/modules/design/route-draft-panel.tsx) and [`zone-draft-panel.tsx`](../../src/modules/design/zone-draft-panel.tsx) own transient draw forms. Recon settings and summaries live in [`reconnaissance-inspector.tsx`](../../src/modules/design/reconnaissance-inspector.tsx); reusable sliders are in [`slider-field.tsx`](../../src/modules/design/slider-field.tsx). These children receive state and callbacks from their route or Studio owner; mission edits still use the existing parent commit/preview paths. [`python-editor.tsx`](../../src/modules/design/python-editor.tsx) contains the non-executing Python draft editor. [`simulation-model.ts`](../../src/modules/simulation/simulation-model.ts) owns deterministic plan construction, injected mock failure, sampling, and telemetry; [`simulation.ts`](../../src/modules/simulation/simulation.ts) owns playback state and timers while re-exporting the stable model API. [`mission-preview-model.ts`](../../src/modules/simulation/mission-preview-model.ts) owns pure preview timeline, position, and capture calculations; [`mission-preview.tsx`](../../src/modules/simulation/mission-preview.tsx) retains the React preview UI and existing public helper exports.
- [`modules/library/`](../../src/modules/library) contains Home, Recent, Projects, workspace resources, Shared with me, mission creation, browser routes, dialogs, and local persistence. [`library.tsx`](../../src/modules/library/library.tsx) composes the Library route and [`library-announce-region.tsx`](../../src/modules/library/library-announce-region.tsx) exposes its single polite status message while retaining the `ms-lib-announce` test hook. [`use-library-projects.ts`](../../src/modules/library/use-library-projects.ts), [`use-library-account-settings.ts`](../../src/modules/library/use-library-account-settings.ts), and [`use-workspace-resources.ts`](../../src/modules/library/use-workspace-resources.ts) own separated data and mutation flows. [`library-sidebar.tsx`](../../src/modules/library/library-sidebar.tsx) renders navigation and workspace/account controls. [`library-main-content.tsx`](../../src/modules/library/library-main-content.tsx) routes to page slices under [`pages/`](../../src/modules/library/pages), while [`project-pages.tsx`](../../src/modules/library/project-pages.tsx) renders Projects and project detail. [`library-cards.tsx`](../../src/modules/library/library-cards.tsx), [`library-card-renderers.tsx`](../../src/modules/library/library-card-renderers.tsx), and [`library-presentation.tsx`](../../src/modules/library/library-presentation.tsx) separate card content, action construction, and shared presentation. Project, Recent, and shared Mission cards use one shared Mission-card renderer; 2D cards use an Esri satellite thumbnail based on the saved mission origin. [`shared/map-tiles.ts`](../../src/shared/map-tiles.ts) owns the satellite tile template and attribution shared by Library thumbnails and scene basemap metadata. AI model categories combine SkyTrack, Workspace-member, and current-user models into All, Members, and Me views. [`library-dialogs-host.tsx`](../../src/modules/library/library-dialogs-host.tsx) composes dialog families; individual forms remain in their leaf modules. These modules preserve the existing store formats, data-test IDs, and UI class names. [`database/store.ts`](../../src/modules/library/database/store.ts) parses persisted JSON as `unknown`, validates the version and record shape, then stores workspace-qualified project and mission data in `localStorage`; older projects without `workspaceId` load into the default Workspace. [`database/drone-store.ts`](../../src/modules/library/database/drone-store.ts) owns the separate versioned local Drone profile store; profiles include optional use-case, frame fit, payload/performance values, profile/component source metadata, and extensible component specifications. Version-1 Drone profiles migrate to version 2; compatibility is not evaluated. Mission records retain a Drone profile ID plus the legacy display label. [`database/workspace-resources-store.ts`](../../src/modules/library/database/workspace-resources-store.ts) owns versioned, Workspace-scoped World and AI model metadata plus labeled Sample fixtures. `Blank space` remains a system 2D World. Registered Worlds store a source mission or user-entered flight reference and an opaque reconstruction reference; no reconstruction files are uploaded or processed. [`workspace-data.ts`](../../src/modules/library/workspace-data.ts) owns Workspace and read-only shared-project fixtures. The active Workspace selection is stored locally. The route shell loads and saves Studio snapshots by stable mission ID. Mission cards display `worldType` and World.
- [`index.css`](../../src/index.css) owns route styles and imports the four contiguous [`library-chunk-*.css`](../../src/styles) files in order at the Library style position. Keep those chunks byte-contiguous with their source order when editing; do not regroup selectors across chunks. The Library sidebar follows the supplied reference for layout and content placement only; colors, surfaces, focus states, and corner radii use `skytrack-ui` semantic tokens. Use components from `skytrack-ui` for controls. [`shared/storage-keys.ts`](../../src/shared/storage-keys.ts) records the exact browser storage keys and versioned payload identifiers; persistence behavior remains in its owning modules.

## Mission and state logic

- `StudioMission` is the design source of truth. Geometry uses local ENU meters (`x` east, `y` north, `z` up) anchored to per-mission `origin`; old missions fall back to Redlands.
- Committed edits go through `commit`: snapshot current mission for undo, clear redo, update mission, clear selection. Inspector drags can preview transient state, then commit or cancel as one edit.
- Drawing draft, active tool, selected entity, camera state, basemap, and view toggles are UI state; drafts do not change the mission until committed.
- Area generation: polygon/circle footprint → clipped serpentine scan lines → traversal waypoints tagged `generatedByArea`. With Recon enabled, Front overlap sets along-track photo spacing and Side overlap sets cross-track lane spacing from the mock camera footprint; generated photo actions, markers, and downstream Preview/Simulation use the same Area waypoints. Recon-off Areas retain manual `lineSpacingM`. Area `Orientation` sets lane direction; Area Recon `Double grid` adds a perpendicular crosshatch pass. Area changes regenerate those waypoints. Avoid changes reroute intersecting legs with generated detours. Generated points keep derived XY; explicit per-point altitude overrides survive regeneration only while the point still matches the same generated coordinates. Avoid altitude edits remain subject to mission validation.
- Camera footprint and Recon estimates: photo-action pitch overrides Recon pitch. 2D, 3D, and Preview share the mock camera ground projection; Nadir lands below its waypoint and oblique pitch projects forward. Projection uses a flat z=0 reference plane and is conceptual, not terrain-aware or payload-calibrated. In 2D, Area Recon altitude is labeled AGL and drives the mock GSD/footprint and regenerated photo density. Design-card duration/battery are Area-segment estimates; Preview duration covers the full mock route, including transfers and Home paths.
- Mission type is `worldType`: `2D` means photogrammetry; `3D` means legacy 3D mission. The main scene uses Cesium for both. 2D uses Blank space and Recon flight altitude for Area scan; 3D Areas use their saved base altitude and take-off altitude rules. Blank space 3D shows a local grid; non-blank 3D Worlds use local terrain fixtures. Basemap is available in 2D and non-blank 3D.
- Home (`spawn`) is a ground location. `takeoffAltM` sets climb height. Area flight height in 2D comes from Area Recon altitude; Area flight height in 3D uses `max(baseAltM, takeoffAltM)`.
- `validateMission` plus transfer validation gates Simulation. `buildSimPlan` orders routes, Areas, transfers, actions, and optional return-home. Simulation is a prototype estimate, not drone control.

## User flow

1. Open a Library page directly by URL or navigate within Library. Create a mission to store its Library record, then open it at `/mission/:missionId`. The mission's complete design state is saved to the browser when Save is pressed and restored when that URL is opened again. The browser title follows the active page name.
2. Choose drone and open World card to choose mission type. 2D fixes World to Blank space; 3D allows mock Worlds.
3. Set Home, then draw Route, Area, or Avoid in any order. Place points on the scene; close and commit polygons. Area commit generates scan lanes and photo waypoints. Area-only missions remain valid and expose END behavior; Route can be added later.
4. Select an entity to edit it in the right inspector. Recon settings preview generated Area results while editing.
5. Resolve validation errors, then enter Simulation. Play, pause, scrub, or inspect estimated flight. Design edits abort an active simulation.
6. Save in the prototype to record mission state in the standalone app's local JSON store. This does not sync to a server and is not a real drone command.

## Agent change guide

- Change domain rules in their owning `domain/` module; preserve public imports through the `domain/mission-model.ts` compatibility barrel.
- Change Viewer ownership in `modules/scene/mission-scene.tsx`, runtime wiring in `scene-viewer-runtime.ts`, camera arbitration in `scene-camera-gestures.ts`, and entity pick/edit flows in the `scene-edit-gestures.ts` coordinator and its lifecycle helpers. Keep reusable entity-ID/coordinate helpers in `mission-scene-helpers.ts`.
- Change inspector behavior in `modules/design/`; keep Python draft editing in `python-editor.tsx` and toolbar leaf controls in `design-controls.tsx`. Simulation plan/playback stays in `modules/simulation/`.
- Preserve the boundary between authored and generated waypoints. Recompute generated geometry when its inputs change. Keep undo/redo and validation on the normal commit path.
- For map edits, distinguish `worldType` from basemap style and World fixture. Do not treat “2D photogrammetry” as a separate map renderer.
